# V0.4.2 in-guest transport harness

**Status: harness implemented; live execution blocked by unavailable KVM.** The
rebuilt ISO contains the V0.4.2 harness, but the retained QEMU image could not
start because the Docker Desktop KVM device exists yet QEMU reports
`Could not access KVM kernel module: No such device`. Docker was intentionally
not restarted because other workloads depend on it. No in-guest transport result
is claimed.

## What the harness adds

After the installed reader task and retention check, `vm/run-sentinel.ps1` now:

1. pushes the installed database to an unused collector port with zero retries
   and expects failure without advancing the local watermark;
2. starts a local `sentinelctl collector` with the lab token and rules;
3. pushes the installed database in batches and records target event counts;
4. resets the sender acknowledgement and re-sends, expecting duplicates;
5. appends a controlled process after the first push and verifies an
   incremental accepted batch;
6. pushes again with no source growth and expects zero batches;
7. stops the collector, copies the target database, and gates the harness result
   on transport success.

The transport block uses only loopback and the same token/allowlist/envelope
implementation as V0.4.1. It does not prove external network behavior or TLS.

## CLI addition

`push --reset-ack` explicitly resets the local acknowledged sensor sequence for
the target collector before draining. It is an operator recovery/test tool for
replaying already-acknowledged events; the collector remains idempotent.

## Limits

- The in-guest assertions are implemented but unexecuted on this host because
  KVM is currently unavailable to Docker. Restarting Docker was ruled out by the
  operator.
- The harness tests one local sensor and loopback collector; multi-sensor live
  merge, external network failure, TLS, and collector restart remain fixture
  coverage.
- `--reset-ack` intentionally causes a full re-send; it must not be used as a
  routine drain.
- QEMU images/disks were retained; only the stopped `sentinel-qemu-1` container
  was removed.
