# V0.4.1 bounded remote transport

**Status: host/fixture pass; rebuilt lab verification passed; live transport not run.** This slice adds one
explicit, versioned HTTP push path from a local Sentinel sensor store to a
collector. It is not a fleet control plane, remote shell, compression layer, or
TLS deployment.

## Envelope

`sentinel.transport/v1` batch fields:

- batch id and creation time;
- sensor, host, incarnation, channel, and config generation;
- clock offset and clock uncertainty (metadata, not applied to timestamps);
- first/last sensor sequence;
- final source bookmark;
- ordered events and coverage gaps;
- canonical payload hash over the event/gap references.

The collector validates format, identities, sequence order, duplicate source
keys, event count, payload hash, token, and optional sensor allowlist before
writing. A batch with an invalid envelope is rejected without a database write.

## Delivery contract

- **At-least-once.** A sender retries a batch on connection failure, non-2xx
  response, or missing/invalid acknowledgement.
- **Idempotent.** The collector persists by the local event source key; duplicate
  events are counted and acknowledged, not duplicated.
- **Ack after commit.** The collector appends gaps, events, alerts, and the final
  bookmark before returning the acknowledgement.
- **Bounded batches.** `--batch-size` limits memory per HTTP request; unacked
  source rows remain in the local store. A collector outage does not advance the
  local transport watermark.
- **Local state.** The sender stores the last acknowledged sensor sequence in
  the source database under the collector URI. A lost acknowledgement causes a
  resend; the collector deduplicates it.
- **Explicit trust surface.** An optional `X-Sentinel-Token` is required when
  configured. An optional `--allow-sensors` list rejects sensors outside the
  local enrollment decision. Neither is a remote identity attestation.

## Collector storage

Each sensor identity writes to `<root>/<sensor>-<hash>.db`. The collector:
- initializes/uses the same local schema;
- persists the declared sensor/host enrollment and clock metadata;
- stores gaps, normalizes events through the existing store transaction;
- evaluates the configured rules against accepted events using the same engine;
- updates the bookmark only to the batch's final event (not the source store's
  current head);
- returns accepted/duplicate counts and the acknowledged sensor sequence.

The resulting databases are directly consumable by `sentinelctl fleet`.

## Commands

```bash
# Collector: loopback only in this slice.
dotnet run --project src/sentinelctl -- collector \
  --listen "http://127.0.0.1:18099/" --root data/collector \
  --rules rules --token "local-secret" --allow-sensors "sensor-a;sensor-b"

# Sensor push. The source store already has explicit enrollment metadata.
dotnet run --project src/sentinelctl -- push \
  --db data/sensor-a.db --collector "http://127.0.0.1:18099/" \
  --token "local-secret" --batch-size 100 --retries 3

# Collector stores are normal fleet inputs.
dotnet run --project src/sentinelctl -- fleet --dbs "data/collector/*.db"
```

The CLI collector runs until Ctrl+C. The push command drains all currently
available batches and exits.

## Limits

- HTTP loopback/native-network only; no TLS, certificate pinning, compression, or
  proxy behavior. The optional token is a shared secret, not an identity proof.
- One-way push. There is no remote command, enrollment API, configuration
  distribution, response action, or central query service.
- The sender's outbox is the local event store plus a bounded HTTP batch; there
  is no separate spool file or disk-pressure policy beyond store retention.
- Gaps are resent with each batch and deduplicated by gap id; there is no
  separate gap acknowledgement watermark.
- The collector evaluates rules locally; it does not carry the source alert set
  as an authoritative result. No cross-host correlation is performed.
- The fresh disposable VM lab was rebuilt after cleanup and Windows installed.
  Its first harness run exposed a concurrent SQLite-lock failure in retention
  purge; commit `986183c` added bounded retry. A later run with the rebuilt ISO
  passed: `ok:true`, `retention_ok:true`, purge 38 rows / 7 raw payloads,
  post-purge append, restore of 24 events, reboot/resume, and teardown.
  Evidence: `vm/results-v041-live-final` (ignored by Git).
- The harness does not yet exercise transport in-guest. V0.4.1 transport remains
  fixture/CLI-verified rather than VM-transport-verified.
